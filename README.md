# 有序 · 任务管理

软件工程课堂实践项目，依据《课堂实践.pptx》，使用 Vue 3、Vite、Tailwind CSS、JavaScript 和 localStorage 开发，无后端。

## 功能

- 任务新增、查看、编辑、删除；标题必填，描述选填，删除前确认。
- 待办／进行中／完成三种状态；高（红）、中（黄）、低（绿）三档优先级。
- 列表与三列看板切换，拖拽卡片改变状态。
- 深色模式与任务数据保存在当前浏览器中，刷新后保留。

## 下载与运行

安装 Node.js 24（含 npm），下载并解压仓库，在含 `package.json` 的目录打开终端：

```bash
npm ci
npm run dev
```

首次安装依赖需要联网。打开终端显示的网址，通常为 `http://127.0.0.1:5173/`；端口占用时以终端输出为准。使用时保持终端运行，按 `Ctrl+C` 停止，不能直接双击 `index.html`。后续启动只需 `npm run dev`。

任务数据不随源码分发，首次使用为空列表；不同浏览器或地址的数据独立，清除网站数据会删除任务。

验证命令：

```bash
npm test         # 自动测试
npm run build   # 构建到 dist
npm run preview # 本地预览构建结果
```

## 提示词与开发过程

以下根据实际对话整理。引号内为用户原话；Plan 模式内容为 AI 生成计划的摘要，不是逐字对话记录。

### 1. 用户提出任务并确定范围

> 看一下课堂实践这个ppt，准备来实现一下这个东西

AI 读取课件全部 4 页，提取功能、技术栈和课堂展示要求，并检查本地开发环境。用户在选项中选择“课堂标准版（推荐）”：覆盖课件全部功能，按多轮开发与验证推进，准备简短演示流程。

### 2. AI 在 Plan 模式生成实现计划（摘要）

- **目标与范围**：在独立的 `task-manager` 目录实现可本地运行、可课堂演示的应用；采用课件推荐技术栈，不加入登录、后端或云同步。
- **交互规则**：表单弹窗支持新增和编辑，标题去除首尾空格后不能为空，默认“待办／中优先级”；提供详情与删除确认，列表和看板共享数据。
- **实现顺序**：项目骨架 → 核心任务功能 → 数据持久化与主题 → 看板拖拽与交付。组件划分为表单、卡片、列表、看板，集中管理任务状态和存储逻辑。
- **异常处理**：读取或写入 localStorage 失败时明确提示，避免将保存失败显示为成功。
- **验收标准**：新增、编辑、删除正确；拖拽与视图切换同步；刷新后任务和主题保留；验证空白标题、空数据及存储异常；运行测试、生产构建和浏览器检查。
- **开发流程**：每轮说明目标、实现、验证，再提交 Git；交付运行说明和课堂演示步骤。

### 3. 用户要求执行与继续

用户发送：

> PLEASE IMPLEMENT THIS PLAN:

随后附上完整的《任务管理应用课堂实现方案》，即上一节摘要所对应的计划，要求按计划实现。

开发过程中，用户又发送：

> ok那继续做这个任务

AI 继续完成看板、视图切换与交付说明。实际提交将计划中的持久化、主题和看板阶段合并在同一轮中。

### 4. 用户要求交付验证

> 可以推送。然后你确认提交后的结果老师能下载之后运行就可以

AI 用已提交源码导出全新副本，执行依赖安装、测试、构建和浏览器验证，并补全下载运行说明。检查时修复了取消拖拽后可能残留拖拽状态的问题。

## 课堂演示顺序

新增任务 → 编辑状态与优先级 → 看板拖拽 → 切回列表 → 刷新验证保存 → 切换主题 → 取消与确认删除。最后结合上述提示词、计划和 Git 提交说明迭代过程。
